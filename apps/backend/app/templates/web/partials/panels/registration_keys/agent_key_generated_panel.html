How to Use This Key

{# color-mode: white on the fixed bg-brand-500 step marker — the brand surface does not flip #}
1

Leave the Agent's Configuration As It Is

Do not put this key in LUXSWIRL_AUTH_KEY: that variable holds the agent's registration key, which it needs to fetch its own key. The agent keeps its key in its encrypted credentials file (/app/data/agent_credentials.json).

{# color-mode: white on the fixed bg-brand-500 step marker — the brand surface does not flip #}
2
{% if recoverable %}

Wait One Heartbeat

The old key is now invalid. No restart is needed: within a few heartbeats the agent logs "Agent-specific key saved and activated". Its registration key must still be active.

{% else %}

Activate, or Approve the Agent That Registers Again

A revoked agent logs "registering again; approve the new agent" and appears as a new pending agent; one with no secret at all logs "holds no recovery secret". Its registration key must still be active.

{% endif %}
{# color-mode: white on the fixed bg-brand-500 step marker — the brand surface does not flip #}
3

Key Recovery

The agent fetches its key from /api/v1/agent/{{ agent.id }}/recover-key with its registration key and the recovery secret in its credentials file. An agent that lost its credentials file registers again.
