# 2026.11.0 — 2026-11-10

First release since v1.0.21 (2026-06-26): 793 commits. It folds in the never-tagged 2026.09.0 draft. The theme is a designed API surface (admin API, scoped tokens, MCP, versioned agent protocol) on top of a security pass across tenancy-free but role-bound data: viewers, /metrics, SSRF, encryption at rest, agent isolation.

**Read before deploying:** the public git history was rewritten (LUXSWIRL-532), 18 migrations run on first start and several rewrite stored data, the agent protocol moved with no aliases (1.0.21 agents cannot talk to this server), two settings became required (ALLOWED_HOSTS, SECURITY\_\_FIELD_ENCRYPTION_KEY), and the agent no longer loads the env file. The deploy runbook is the first item under Notes.

## Schema / Migrations

Migrations run on server start: compose.yml's luxswirl_server command is `alembic upgrade head && exec uvicorn …`. The image's own CMD is bare uvicorn (apps/backend/Dockerfile), so a deployment that does not use the shipped compose command must run `alembic upgrade head` itself. alembic/env.py loads SECURITY\_\_FIELD_ENCRYPTION_KEY and refuses a key that cannot decrypt every stored token before any revision runs (LUXSWIRL-376, 476).

**000_initial_schema.py (43a72b7c97c8) was rewritten in place in this window** (2,300 lines, mostly reformatting). Compared structurally (the parsed `upgrade()`, same 19 tables and 296 columns, same indexes; `downgrade()` identical), three things differ, and they reach fresh installs only, because a database already at 43a72b7c97c8 never re-runs it: `agents.first_seen`/`last_seen` default to `now()` instead of the literal `'NOW()'` (which Postgres froze to the creation time); and the unique constraints on `settings.key` and `status_pages.slug` are named `uq_settings_key` and `uq_status_page_slug` (1.0.21 left them to Postgres's auto names). No runtime effect: the app sets both timestamps on every agent create and no code names either constraint. An upgraded install keeps the 1.0.21 shape until LUXSWIRL-537 aligns it.

1. **[release host, owner]** `make release`. Expect both `ghcr.io/luxardolabs/luxswirl-backend:2026.11.0` and `-agent:2026.11.0` built, scanned and pushed, then the GitHub Release. It refuses a dirty tree, a released version, or an untagged HEAD; VERSION must read 2026.11.0 and the commit must be tagged v2026.11.0. On failure: fix and re-run. A pushed version is immutable, so never force it; bump VERSION instead. Rollback: none (nothing deployed yet).

1. **[every clone: release host, prod, dev]** The history rewrite (LUXSWIRL-532): `git fetch origin && git reset --hard origin/main && git fetch --tags --force`, or re-clone. Expect `git rev-parse v1.0.21` to print the new sha and `git status` clean. On failure (local commits on old history): re-clone and cherry-pick by content. Never push an old branch.

1. **[prod]** Back up the database, because migrations 001, 007, 011 and 014–018 rewrite or delete data: `make db-backup` (a `pg_dump` to backups/YYYY/MM/DD/luxswirl\_<ts>.dump), or without the repo `docker exec luxswirl_timescaledb pg_dump -U luxswirl -Fc luxswirl > pre-2026.11.0-$(date +%Y%m%d_%H%M%S).dump`; then `pg_restore -l <that file> | head`. Expect a non-empty file and a table of contents listing checks and check_results. On failure: stop, do not upgrade. Also copy the agent credentials: `cp -a ./data/agent /backups/luxswirl/agent-data-pre-2026.11.0`.

1. **[prod]** Capture the field-encryption key while 1.0.21 is still running: `grep -c '^SECURITY__FIELD_ENCRYPTION_KEY=.\+' .env.prod || docker exec luxswirl_server cat /app/data/field_encryption_key`. Expect either a count of 1 or the key the old server generated. Put that exact value in .env.prod as `SECURITY__FIELD_ENCRYPTION_KEY=`. Never generate a new one: a new key cannot read the stored credentials, and 2026.11.0 has no /app/data mount to find the old file. On failure (neither exists): the 1.0.21 server ran without a key and stored plaintext. Generate one (`python3 -c 'from cryptography.fernet import Fernet; print(Fernet.generate_key().decode())'`) and keep it; migration 018 encrypts the plaintext under it.

1. **[prod]** Bring the stack files to the release: `git checkout v2026.11.0 -- compose.yml .env.example nginx/` (repo checkout on prod), then edit .env.prod:

   - `TAG=2026.11.0`
   - `ALLOWED_HOSTS=<public host>,luxswirl_server`. Required, no scheme or port.
   - `SECURITY__FIELD_ENCRYPTION_KEY=` from step 4.
   - Remove `SECURITY__AUTH_TOKENS` and `SECURITY__SECRET_KEY` (both ignored now), and rename any `SECURITY__INITIAL_ADMIN_*` to `INITIAL_ADMIN_*`.
   - If the reverse proxy is not the compose service `nginx`, set `SECURITY__TRUSTED_PROXY_HOSTS='["<name>"]'` or `SECURITY__TRUSTED_PROXY_NETWORKS='["<cidr>"]'`. Otherwise every client shares the proxy's rate-limit bucket.
   - Any variable the agent used to inherit from this file (proxy, TZ) must be added under x-agent-environment in compose.yml. Optionally set `AGENT_MEM_LIMIT` and `AGENT_PIDS_LIMIT`.
   - Compare nginx/conf.d/luxswirl.conf with its .example: it overwrites X-Forwarded-For and has a default_server that refuses unknown Hosts.

   Expect `docker compose --env-file .env.prod config --quiet` to exit 0. On failure: it names the missing variable. Rollback: `git checkout v1.0.21 -- compose.yml nginx/` and restore .env.prod from your copy.

1. **[prod]** `docker compose --env-file .env.prod pull`. Expect both images at 2026.11.0. On failure: check registry reachability and that step 1 published.

1. **[prod]** Plan for the agents. 1.0.21 agents use the old protocol paths, which no longer exist (no aliases, LUXSWIRL-333), so every agent must move to 2026.11.0 together with the server. The bundled agent in this compose.yml moves with step 8. Standalone agent nodes: step 11.

1. **[prod]** `make prod-up` (runs `docker compose -f compose.yml --env-file .env.prod up -d`), then `docker compose --env-file .env.prod logs -f luxswirl_server` until uvicorn reports it is serving. Expect alembic to log `Running upgrade` 43a72b7c97c8 → … → 3f9c7a1b5e82, plus WARNINGs naming any check it disabled (001/016), any status page it rewrote (015), any rate limit it reset (017), and any value too long to encrypt (018). Save those lines. Then `docker compose --env-file .env.prod ps`: every service healthy.

   - On failure, "refuses to start: ALLOWED_HOSTS": fix step 5.
   - On failure, "encrypted values do not decrypt" (server or alembic): the key is wrong. Set the right one; if two keys wrote the database, `docker compose --env-file .env.prod run --rm luxswirl_server python -m app.scripts.reencrypt_fields` with the other key on stdin (docs/guides/troubleshooting.md).
   - On failure, "no key while some value is plaintext/encrypted": set the key (step 4).
   - Rollback: `docker compose --env-file .env.prod down`; restore the database (`docker compose --env-file .env.prod up -d timescaledb`, drop and recreate the luxswirl database, then `pg_restore -U luxswirl -d luxswirl --clean` from the step 3 dump, run through `docker exec -i luxswirl_timescaledb`); `TAG=1.0.21`; restore compose.yml/nginx from v1.0.21 and the agent data copy; `make prod-up`. The data migrations have no usable downgrade, so restore from the backup; never `alembic downgrade`.

1. **[prod or anywhere]** `curl -fsS https://<public host>:9000/health`. Expect `"status":"healthy"`, `"version":"2026.11.0"` and a commit. Then `curl -s -o /dev/null -w '%{http_code}\n' -H 'Host: forged.invalid' https://<public host>:9000/health` should print 400 (or nginx's 444 / closed connection). On failure: the old container is still serving; recheck step 8.

1. **[operator workstation with the repo]** `make smoke SMOKE_URL=https://<public host>:9000` (add `SMOKE_AUTH_PATH=/metrics` and `SMOKE_AUTH_TOKEN` in the environment if /metrics is token-protected). Expect every probe PASS: /health names the commit, CSS served, forged Host refused, containers healthy, entry points import. On failure: the probe names what broke. Rollback per step 8.

1. **[each standalone agent node]** Update its env file: `LUXSWIRL_SERVER_URL=https://<public host>:9000`, with no path (any old push URL ending in /api/v1/… is refused at startup). Add proxy or TZ variables to x-agent-environment. Then `TAG=2026.11.0`, `docker compose --profile standalone-agent --env-file .env.<env> pull && docker compose --profile standalone-agent --env-file .env.<env> up -d`, then `docker compose --env-file .env.<env> logs --tail 50 luxswirl_agent`. Expect the heartbeat accepted and the agent online in Dashboard > Agents. Pre-flight anywhere: `docker run --rm --env-file .env.<env> ghcr.io/luxardolabs/luxswirl-agent:2026.11.0 python -m app.main --validate-only` exits 0. On failure: an agent that cannot recover its key re-registers as pending. Approve it in the Dashboard (agents registered before migration 002 have no recovery secret). Rollback: TAG=1.0.21 works only with a 1.0.21 server.

1. **[Dashboard, admin]**

   - Agents: every agent online, none stuck pending; approve any that re-registered.
   - Checks: re-enable any check migration 001/016 disabled, after fixing its HTTP method or DNS record type (the step 8 log names them).
   - Status pages: review any page migration 015 rewrote.
   - Settings > Security: confirm the rate limits.
   - Settings > API Keys: create the /metrics bearer token if /metrics used SECURITY\_\_AUTH_TOKENS.

1. **[Prometheus/Grafana]** Update scrape auth (step 12's token) and every query, dashboard and alert rule keyed on the luxswirl\_\* `target` label. The values are now scheme, host and port only, so series restart under new label values.

1. **[dev / sandbox stacks]** `make dev-deploy` from the main checkout (never a worktree), after `.env.dev` and `.env.sandbox` get the step 5 settings. Expect publish-sha, dev-pin and smoke PASS. Rollback: `make dev-pin TAG=sha-<previous commit>` (no rebuild; restore the DB backup as well if migrations ran).

### Other notes

- **Compatibility is one-way:** an agent needs a server from its own release or later, and this server refuses every 1.0.21 agent request (moved paths). Upgrade server and agents in one window.
- **Not yet checked on a deployed stack:** the owner's browser checks (no CSP violations across the pages, LUXSWIRL-315 and 468) and the two-agent failover run (LUXSWIRL-300). The suite cannot run a browser or kill an agent.
- **Known issue:** an agent report that holds a result for a check deleted while the report was in flight fails the whole batch with a 500; the agent's later send succeeds (LUXSWIRL-534).
- **Still open, tracked:** webhook subscriptions (LUXSWIRL-377); clients/CLI/Terraform (378); per-token IP allowlist (379); admin view of users' tokens (338); agent checks-cache constant key (524); rootless Docker with negative oom_score_adj untried (462); five hand-made status-page filter shapes emptied by 015 (419).
- 2026.09.0 was drafted and never tagged; this release supersedes it, and its drafts are folded in above. The 2026.09.0 draft's API fixes (import 500, export-agent-config, clone, alert counts) shipped against the management API that LUXSWIRL-287 later removed. They are recorded here as history, not as live routes.
