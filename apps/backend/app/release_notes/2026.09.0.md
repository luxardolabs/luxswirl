# 2026.09.0 — 2026-09-07

Certificate warnings, check settings and alert snoozing now do what you configured them to do — and when something does go wrong, the app says so instead of pretending it worked.

## NEW

- **Every page is exercised before release** `Dashboard` — A page that would fail to load now fails our checks first, so it doesn't reach you.

## IMPROVED

- **Failures are visible** `Dashboard` — When an action fails, you get an error message instead of a screen that looks like it worked. Previously a failure could come back looking like a normal result.
- **Faster lists and dashboards** `Dashboard` — Pages that show many checks or agents at once load with far fewer database round-trips.
- **Reliability** `Dashboard` `API` `Agent` — A large amount of behind-the-scenes stability work across the web pages, the API and the agent.

## FIXED

- **Certificate expiry ignored your warning settings** `Dashboard` `Agent` — If you set a 7-day warning window, certificates were still judged against the built-in 30 days. Both the agent and the check detail panel now use the windows you configured.
- **Import and export were open to anyone** `API` — Exporting your check inventory, including internal hostnames, did not require a token, and neither did importing checks. All three routes now require one. If you expose the API beyond your network, treat any inventory that could have been read as disclosed.
- **Un-snoozing an alert did nothing** `Dashboard` — The request was rejected before it reached the alert, so a snoozed alert stayed snoozed.
- **A check's dependency was never shown** `Dashboard` — The check detail panel has a section for the parent check it depends on; it never appeared.
- **"Max Retries" was not saved** `Dashboard` — The field accepted a value on the check form and then discarded it.
- **Response-time sparklines drew a broken line** `Dashboard` — Roughly one in four checks rendered a malformed graph.
- **Importing checks through the API always failed** `API` — Every import returned a server error.
- **Exporting an agent's configuration never returned** `API` — The request would not complete.
- **Alert forms showed "Variables: , , ,"** `Dashboard` — The list of available variables rendered empty instead of showing the placeholder names.
- **Some forms posted to the wrong address** `Dashboard` — A naming collision sent a handful of form submissions to the API instead of the page that owned them.
- **Malformed requests returned a server error** `API` — A request with a broken body now comes back as an invalid-request response rather than a server error.
- **Deleting a user used a browser pop-up** `Dashboard` — It now uses the same inline confirm as the rest of the app.
