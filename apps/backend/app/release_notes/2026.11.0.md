# 2026.11.0 — 2026-11-10

You can now run LuxSwirl from scripts and from AI assistants. Viewers see far less of your secrets, and alerts, retries and status pages now do what you set them to. Upgrade your agents at the same time as the server: agents from earlier versions cannot talk to this one.

The labels after each item name the part of LuxSwirl it changes: `Dashboard` (the web app), `API` (the admin API), `MCP` (AI assistants), `Agent` (the monitoring agent) and `Status pages` (the pages you publish).

## NEW

- **Admin API** `API` — You can manage checks, agents, alerts, notifications, status pages, users, settings and jobs from your own scripts, with the same permissions you have in the web app.
- **Personal API tokens** `Dashboard` `API` — You create and revoke your own tokens in My Account and choose read only, read and write, or full access for each one.
- **AI assistants (MCP)** `MCP` — You can connect an AI assistant with one of your tokens to read your monitoring and make safe changes, such as enabling a check or snoozing an alert.
- **API activity** `Dashboard` — Admins see every call made through the API or an AI assistant under Settings, and you see your own in My Account.
- **Alerts for silence** `Dashboard` — You can be alerted when a check stops reporting or an agent goes offline, not only when a check fails.
- **Certificate alert when expiry can't be read** `Dashboard` — An SSL expiry alert now tells you when a certificate's expiry date cannot be read, then recovers once it can.
- **Archive agents** `Dashboard` — You can archive an agent you no longer use and restore it later, instead of deleting it and its history.
- **Refused reports are kept** `Agent` `Dashboard` — Results the server refuses as invalid are set aside instead of blocking the agent's queue, and the agent's card shows how many there are.
- **Running jobs** `Dashboard` — Jobs now show as running while they run, and you can cancel one in progress.
- **Agent setup check** `Agent` — The agent checks its settings at startup and tells you exactly what is wrong instead of starting half-configured.

## IMPROVED

- **Viewers see less of your secrets** `Dashboard` `API` `MCP` — Viewers now see a check's address as its scheme, host and port only. Passwords, keys, scripts, queries, error details and job results are masked or hidden, and notification settings are hidden entirely.
- **Screenshots and traces are for editors** `Dashboard` — Only editors and admins can open a synthetic check's screenshots and traces.
- **Prometheus labels** `Dashboard` — The target label in the metrics Prometheus reads now carries only scheme, host and port, so update any graph or alert rule that matches on it.
- **Safer agent** `Agent` — The agent runs locked down, with no extra privileges, a read-only filesystem and memory and process limits, and it no longer receives the server's secrets.
- **Private network blocking goes further** `Dashboard` `Agent` — With Block Private Network Targets on, loopback and carrier-grade NAT addresses are blocked too, and the rule now also covers webhooks, Home Assistant, network scans and the bulk-create preview.
- **Agents fix their own keys** `Agent` — After you regenerate an agent's key it picks up the new one by itself. After you revoke it, the agent asks to be approved again.
- **Check retries** `Agent` — Retry attempts and the retry interval you set on a check now actually retry it before it counts as down.
- **Check refresh** `Agent` — Agents now pick up check changes on the sync interval you set.
- **Status page editor** `Dashboard` `Status pages` — Two people can edit one page at once, typing is no longer lost when the list redraws, and quick additions are no longer dropped.
- **Faster status pages and dashboard** `Dashboard` `Status pages` — Uptime figures load quickly even with months of history.
- **Export and import keep everything** `Dashboard` `API` — An exported check now comes back with all its settings, database, DNS, synthetic and certificate options included.
- **Sign-in protection** `Dashboard` — Rapid parallel password guesses no longer slip past the lockout, and changing your password now locks after repeated wrong attempts.
- **Rate-limit settings take effect** `Dashboard` — Changing a rate limit in Settings now changes it, and a value that isn't valid is shown as not applied.
- **Clearer error messages** `Dashboard` — When something you enter is refused, you see which field and why, and an action that fails shows an error instead of looking like it worked.
- **Buttons show progress** `Dashboard` — Buttons that talk to the server show a spinner and can't be clicked twice.
- **Deleting users** `Dashboard` — Deleting a user uses the same inline confirm as the rest of the app.
- **Reliability** `Dashboard` `API` `Agent` — Lots of behind-the-scenes stability, speed and security work.

## FIXED

- **Import and export were open to anyone** `API` — In the previous version, exporting your check inventory, including internal hostnames, and importing checks needed no token. If you exposed that version's API beyond your network, treat that inventory as disclosed.
- **Anyone could view check screenshots** `Dashboard` — A synthetic check's screenshots and traces could be opened without signing in.
- **Viewers could read saved passwords** `Dashboard` — A viewer could open a check's or a notification's edit form, or search, and read the passwords and scripts inside.
- **The last admin could be demoted** `Dashboard` — Editing the only active admin into a lower role or deactivating them is now refused.
- **A password reset didn't sign the user out** `Dashboard` — When an admin resets your password, your other sessions now end.
- **Certificate warnings ignored your settings** `Dashboard` `Agent` — Certificates were judged against the built-in 30 days whatever warning window you set.
- **Results from shared checks were lost** `Agent` — Checks set to run on several agents, or spread across them, dropped their results.
- **Agents couldn't upload screenshots** `Agent` — Synthetic check screenshots and traces from agents were refused.
- **Agents stopped sending after one bad batch** `Agent` — A batch the server refused, or one too large for your proxy, blocked everything queued behind it.
- **Some heartbeats failed under load** `Agent` — Busy servers sometimes refused an agent's heartbeat with an error.
- **Status pages and the dashboard failed to load** `Dashboard` `Status pages` — Pages with long uptime windows could time out with an error.
- **A broken status page group stopped the page** `Status pages` — Some groups saved by the old editor made the whole page fail to load, and the editor could not open it to fix them.
- **Reordering a status page dropped checks** `Status pages` — A check the editor wasn't showing, such as one on an archived agent, disappeared when you saved.
- **Cloning a check failed** `Dashboard` — Cloning any check covered by a global alert failed, and a clone's alerts did not keep the original's snooze and on/off state.
- **One alert could stop the others** `Dashboard` — An alert that hit an error stopped every other alert on the same check from firing.
- **Bulk-created checks lost settings** `Dashboard` — Retry and resend-notification values on the bulk HTTP form were not saved.
- **Max Retries was not saved** `Dashboard` — The field accepted a value and then discarded it.
- **Un-snoozing an alert did nothing** `Dashboard` — A snoozed alert stayed snoozed.
- **A check's dependency was never shown** `Dashboard` — The check detail panel's section for the parent check never appeared.
- **Check details failed for synthetic checks** `Dashboard` — The panel errored for scripts that reported no page timings.
- **Job details failed for some scans** `Dashboard` — Discovery jobs and small network scans showed an error instead of their results.
- **Unlock Account did nothing** `Dashboard` — The button on the users list now unlocks the account.
- **New checks showed 0 % uptime** `Dashboard` — A check with no results in the last day now shows no data instead of 0 %.
- **Response-time sparklines were broken** `Dashboard` — About one in four checks drew a malformed graph.
- **Alert forms showed "Variables: , , ,"** `Dashboard` — The list of placeholders you can use now shows their names.
- **Some forms went to the wrong place** `Dashboard` — A handful of form submissions were sent to the wrong address.
- **Text in some fields could run as code** `Dashboard` — A username or tag could be turned into page code in some messages and lists.
- **Alert emails could show raw markup** `Dashboard` — Check names and errors are now shown as text in alert emails.
- **DNS TXT checks failed on long records** `Agent` — Records split across parts, or holding unusual bytes, no longer fail the check.
- **MySQL checks ignored the SSL option** `Agent` — Adding ssl=true to a MySQL check now uses SSL.
